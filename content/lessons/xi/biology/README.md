# Class XI Biology lessons (pilot: Chapter 1)

Authored lesson drafts for Class XI Biology, derived from the owner's current textbook PDF (`11 Class Data/11th Class Biology.pdf`, source `C11-BIO`). Everything here is a **draft**: nothing is academically reviewed or published, and the import tool below never publishes anything. Class XI and Class XII material is never mixed.

## Files

| File | What it is |
| --- | --- |
| `c11-bio-ch1-1.N.json` | The English lesson for topic 1.N, one import document with one item (`external_id` `C11-BIO-CH1-1.N`). |
| `c11-bio-ch1-1.N-ru.json` | The Roman Urdu explanation of the same topic (`C11-BIO-CH1-1.N-RU`, `language: roman_ur`, `variant_of: C11-BIO-CH1-1.N`). A full explanation written for the topic, not a transliteration; it keeps the English item's block structure one-to-one so a reader can switch languages at the same place. |
| `c11-bio-ch1-1.N.coverage.json` | The coverage register for the topic: PDF page span, every textbook figure in that span and what the lesson carries for it, which original figures are archived, and the findings (printed errors, numbering gaps, ambiguities) recorded instead of silently corrected. |
| `figures/` | Rendered original figures (PNG) and `figures.json`, the media-pack manifest with provenance. Generated by `content/tools/figures/render.mjs` from the SVG sources and three.js scenes in `content/tools/figures/`. |

## Figure placeholders

Lesson files name figures by the media pack's `external_id`, never by an archive ID, so the same files import into any environment:

| Placeholder | Becomes |
| --- | --- |
| `"$asset": "<id>"` on a `diagram` | `asset_version_id` |
| `"$poster": "<id>-poster"` on a `model3d` | `poster_asset_version_id` |
| `"$frames": "<id>-frame"` on a `model3d` | `frames` (`<id>-frame-01` … `-16`, in order) |
| `"$image": "<id>"` inside a `fallback` | `image_asset_id` |

`model3d` blocks always carry a reviewed `fallback` (the poster still plus text), so a client older than renderer 2 shows the still.

## Importing into a development API

```bash
python content/tools/import_lessons.py --api http://127.0.0.1:8100
```

Signs in as the dev-seed author (`studio-author@example.com`; set `PORTAL_IMPORT_PASSWORD` otherwise), archives `figures/` as one media pack (idempotent), then imports every English lesson and then every Roman Urdu variant (a variant must follow its base, because the base is checked against the archive at preview time). Each import is a preview followed by a commit, so a file with any error imports nothing. Re-running reports `unchanged` for untouched files and `update` for edited ones.

## Rendering figures again

```bash
node content/tools/figures/render.mjs          # all
node content/tools/figures/render.mjs svg      # the SVG diagrams only
node content/tools/figures/render.mjs scenes   # the three.js models (poster + 16 turntable frames)
```

Needs `apps/web` installed (three.js and Playwright's Chromium come from there). Re-render, then re-run the import: a changed PNG becomes the asset's next version and the lessons pick it up on the next import.

## Conventions worth keeping

- **Quick recap after the full explanation**, never instead of it. Distinctions the textbook draws (ester vs ether lipids, acoelomate vs pseudocoelomate vs coelomate, polyp vs medusa, Pisces vs Tetrapoda) stay distinct.
- **Provenance and corrections** live in the coverage register, not in the lesson text. A printed error is kept as a finding; the lesson uses the correct form and says so.
- **2D first.** Every figure starts as a 2D drawing. A 3D model is made only where a 2D drawing cannot convey the structure (the amniotic egg's layers, polyp against medusa, a sponge's interior, virus shapes, the lipid bilayer), never for charts, hierarchies or tables; speed comes first.
- **Roman Urdu glossing.** The first time a hard Urdu word appears in a topic it is followed by the English word in brackets ("darjon (levels) ka ek nizam (system)"); scientific terms stay in English.
- **Originals only.** Figures are drawn or modelled for the lesson, labelled, captioned in both languages, and never traced from the textbook's pictures or photographs. Photographic figures in the book are covered in the text and marked so in the register.
- **No invented content.** Every paragraph traces to the page span in `source_refs`; the register lists what each figure in that span became.
