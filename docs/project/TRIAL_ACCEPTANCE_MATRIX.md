# Trial acceptance matrix (P14.S8.T3, TRIAL-MATRIX-01)

**Updated:** 2026-10-12. This file lists every trial acceptance scenario from roadmap Section 19: AC29–AC44, AC55 and AC64–AC66. For each one it records:

- the evidence the scenario needs;
- the tests that already cover its isolated protocol path;
- what is still missing.

`apps/api/tests/test_trial_matrix.py` checks this file. It fails if a scenario is missing, if a cited test does not exist, or if a row that needs real-device or payment evidence is marked **Met**.

**Ground rules**

- Device verdicts in the API tests come from the development fixture adapter (`trial_devices.FixtureProvider`). They exercise the decision table. They do **not** show that any real device is recalled. Apple DeviceCheck/App Attest and Google Play Integrity need store accounts and approval (B07, B08). Until then the deployed adapters report "unknown, provider not configured" and never invent a verdict.
- No payment provider is integrated (B06), so no purchase, restore, refund or conversion path is exercised. The API cannot record a fabricated payment success (`test_service_degradation.py::test_no_payment_success_can_be_fabricated`).
- Sandbox and device results never prove live behaviour. Live payment and launch checks stay at P23.S1.

**Status values**

| Status | Meaning |
| --- | --- |
| **Met** | The whole scenario is server-side and tested. |
| **Protocol tested** | The isolated protocol and failure paths are tested; the evidence named in the row is still needed. |
| **Blocked** | The scenario depends on an external capability that does not exist yet. Partial protocol tests are listed. |

**Evidence kinds:** `protocol` (API tests), `browser` (Playwright), `real device` (installable build on a named device; B07/B09), `payment sandbox` (provider sandbox; B06).
