| RECHECK-01 | 2026-10-08 | **Recheck eligibility, scope and duplicates (corrects IMPL-23 after review R04).** A request targets the **current released score version** and must be made within **14 days of that version's release** (§20.10). It is stored structurally in `written_recheck_request`: target version, question positions, optional disputed criteria, reason, requester. The database allows **one request per target version**, so duplicate or concurrent requests open at most one case (a concurrent loser gets 409). Against a first result every question is eligible. Against a corrected result only the questions whose **awarded marks** that correction changed are eligible: unchanged questions already had an independent second look, and reworded feedback alone opens nothing. This keeps appeals against later corrections (§20.10.3) without allowing endless repeats. | IMPL-17 | 2026-10-07 | **Attempt protocol as specified in §10.5.** Every write locks the attempt row and reads `clock_timestamp()` **after** the lock as `admitted_at`.
